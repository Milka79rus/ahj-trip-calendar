# Домашнее задание. Trip Calendar Widget 

[![Netology AHJ](https://github.com/Milka79rus/ahj-trip-calendar/actions/workflows/web.yml/badge.svg)](https://github.com/Milka79rus/ahj-trip-calendar/actions/workflows/web.yml)

Интерактивный виджет выбора дат для сервиса путешествий (выбор даты «Туда» и опциональной даты «Обратно» с переключателем).

##  Особенности и функционал
* **Валидация дат**: Дата «Туда» не может быть раньше текущего дня. Дата «Обратно» заблокирована до активации чекбокса и не может быть раньше даты «Туда».
* **Moment.js**: Вся работа с датами, сдвигами месяцев и форматированием реализована через библиотеку `moment`.
* **Подсветка дат**: Текущая дата (сегодняшний день) выделяется в календаре рамкой. Прошедшие или недоступные даты автоматически блокируются (`disabled`).
* **Переключение месяцев**: Реализована логика пересчета сетки дней при перелистывании месяцев вперед и назад.

##  Архитектура
Проект спроектирован с четким разделением ответственности между бизнес-логикой и интерфейсом, что упрощает тестирование и масштабирование:
1. **`TripCalendarEngine.js` (Чистая логика)**: Класс, отвечающий исключительно за расчеты. Не имеет доступа к DOM (`document`, `window`). Генерирует сетку дней, проверяет состояния блокировок и переключает месяцы.
2. **`TripCalendarWidget.js` (Слой DOM)**: Класс, отвечающий за рендеринг HTML-структуры, динамическое отображение поповеров, генерацию CSS-сетки и обработку кликов пользователя.

##  Стек технологий
* **JavaScript (ES6+)**
* **Moment.js** (работа с датами)
* **Webpack 5** (сборка проекта, минификация, стили)
* **Jest** (Unit-тестирование изолированной логики)
* **Puppeteer** (E2E-тестирование взаимодействия с DOM)
* **CSS Grid Layout** (отрисовка календарной сетки)

##  Команды для запуска и разработки

### Установка зависимостей
```bash
npm install
```

### Запуск режима разработки (Локальный сервер)
```bash
npm start
```

### Сборка проекта (Production)
```bash
npm run build
```

## 🧪 Тестирование

В проекте настроено автоматическое раздельное тестирование логики и интерфейса.

### 1. Unit-тесты (Логика движка)
```bash
npm test
```

### 2. End-to-End (E2E) тесты (Интерфейс)
```bash
npm run e2e
```
*Примечание: В конфигурации Puppeteer прописаны флаги `--no-sandbox` для успешного прохождения пайплайнов в CI/CD (GitHub Actions).*
